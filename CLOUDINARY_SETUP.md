# Cloudinary Direct Upload Setup Guide

## What Changed?
✅ **Removed backend upload route** - No longer needed since uploads go directly to Cloudinary
✅ **Removed multer middleware** - Not required for direct uploads
✅ **Updated frontend helper** - Now uploads directly to Cloudinary with progress tracking

## Required: Create Unsigned Upload Preset

Since you're uploading directly from the frontend, you need to create an **unsigned upload preset** in Cloudinary.

### Steps:

1. **Login to Cloudinary Dashboard**
   - Go to: https://cloudinary.com/console

2. **Navigate to Upload Settings**
   - Click on **Settings** (gear icon)
   - Go to **Upload** tab
   - Scroll to **Upload presets**

3. **Create New Preset**
   - Click **Add upload preset**
   - Set the following:
     - **Preset name**: `school_management_unsigned`
     - **Signing mode**: **Unsigned** (IMPORTANT!)
     - **Folder**: `school_management_uploads` (optional)
     - **Allowed formats**: jpg, png, jpeg, pdf, mp4
     - **Max file size**: 200 MB (or your preferred limit)
     - **Transformations**: 
       - Quality: Auto
       - Format: Auto (for automatic format optimization)

4. **Save the Preset**

### Environment Variables

The `.env` file has been created in the frontend directory:
- `VITE_CLOUDINARY_CLOUD_NAME` - Your cloud name (already set)
- `VITE_CLOUDINARY_UPLOAD_PRESET` - The preset name you created above

## Benefits of Direct Upload

1. **Reduced Server Load** - Files don't pass through your backend
2. **Faster Uploads** - Direct connection to Cloudinary CDN
3. **Better Scalability** - No backend timeout issues for large files
4. **Progress Tracking** - Still maintains upload progress functionality

## Testing

After creating the upload preset, restart your frontend dev server:

```bash
# Stop the current dev server (Ctrl+C)
cd frontend
npm run dev
```

Then test uploading an image/video through your app!

## Security Note

Unsigned uploads are convenient but less secure. For production, consider:
- Setting upload restrictions in the preset (formats, size, etc.)
- Using signed uploads with upload signatures generated by your backend
- Implementing rate limiting on the frontend

For now, unsigned uploads are fine for development and internal use.

## Troubleshooting

### Images Not Uploading (Videos Work Fine)

If videos upload successfully but images fail, the most common causes are:

**1. Upload Preset Not Created**
- Make sure you created the `school_management_unsigned` preset in Cloudinary dashboard
- Verify the preset name matches EXACTLY (case-sensitive)
- Ensure "Signing Mode" is set to "Unsigned"

**2. Allowed Formats Restriction**
- In your upload preset settings, check "Allowed formats"
- Make sure image formats are included: `jpg`, `png`, `jpeg`, `gif`, `webp`
- If it's empty, it should allow all formats by default

**3. Check Browser Console**
- Open Developer Tools (F12)
- Go to Console tab
- Try uploading an image
- Look for detailed error messages with emojis (📤, ❌, ✅ etc.)
- Share the error message if you need help

**4. Verify Environment Variables**
- Make sure you **restarted the frontend dev server** after creating `.env`
- Check if the values are loaded:
  ```javascript
  console.log(import.meta.env.VITE_CLOUDINARY_CLOUD_NAME)
  console.log(import.meta.env.VITE_CLOUDINARY_UPLOAD_PRESET)
  ```

**5. Common Error Messages**

| Error | Cause | Fix |
|-------|-------|-----|
| "Upload preset not found" | Preset doesn't exist or wrong name | Create preset or fix name in `.env` |
| "Invalid image file" | File format not allowed | Add format to preset's allowed formats |
| "Unauthorized" | Preset is signed, not unsigned | Change preset to "Unsigned" mode |
| "Resource not found" | Wrong cloud name | Verify `VITE_CLOUDINARY_CLOUD_NAME` |
